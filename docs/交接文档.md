## 0. 一句话交接

项目是 **Web PWA（React 19 + TS + Vite + Tailwind v4 + Zustand）前端 + NestJS 11 + TypeORM + better-sqlite3 后端** 的智能提醒与健康管理社交应用。**M0~M4 已完成并全部提交**，当前停在 M4 收尾；下一步是 **M5 里程碑**（周报月报生成、热力图完善、成就系统、数据导出/注销、部署手册、UI 全面评审与发布检查）。

## 1. 项目概览

### 1.1 产品定位
以"定时提醒"为核心，融合用药管理、短时锻炼、生活习惯养成与社交激励的健康管理应用。Slogan：*准时提醒，温柔守护——布谷，你的健康生活管家。* 完整需求见 `docs/需求分析文档.md` 与 `docx/布谷企划-app制作-extracted.md`。

## 4. 如何运行

### 4.1 首次准备
```bash
# 后端
cd backend
cp .env.example .env      # 按需填 VAPID 密钥（npx web-push generate-vapid-keys）
npm install

# 前端
cd ../frontend
npm install
```

### 4.2 启动开发
```bash
# 终端 1：后端（默认 http://localhost:3000）
cd backend && npm run start:dev

# 终端 2：前端（默认 http://localhost:5173，/api 代理到 3000）
cd frontend && npm run dev
```
访问 `http://localhost:5173`。**注意**：如果 5173 被占用 Vite 会换端口（前端代理与 CORS 白名单都按 5173 配置）；如果 API 行为异常（如 500 / 404），先检查是否有旧 node 进程占用 3000 端口——**`taskkill //F //IM node.exe` 后干净重启**（历史踩坑：旧进程继续服务旧代码导致"新功能不生效"假象）。

### 4.3 测试
```bash
cd backend && npm test          # Jest 单测（当前 61 通过）
cd frontend && npm test         # Vitest（当前 20 通过，tests/unit/ 目录）
cd frontend && npm run test:e2e # Playwright——2026-08-29 已固化：自动拉起前后端，E2E-01/02/06/10 4/4 通过（需先 npm run build 后端 dist）
```

### 4.4 Swagger / 调试

### 5.3 提醒触发机制（前端侧，重点理解）
`features/reminders/ReminderScheduler.tsx`（挂载在 App 根）+ `useReminderScheduler.ts`：
1. 登录后轮询 `GET /api/v1/reminders/today`（15s）+ 监听事件总线 `cuckoo:reminders-changed`（增删改提醒后触发刷新）
2. 从 `nextTriggerAt` 计算最近触发点，setTimeout 到时弹出 `ReminderOverlay` 全屏弹窗
3. 弹窗操作：完成（可带拍照挑战 flow）/ 延迟（预设 + 自定义分钟）/ 跳过 → 调 `POST /api/v1/reminders/:id/ack` 或 `:id/delay`
4. 页面关闭时：依赖 Web Push / SW（PWA 安装后 `push.ts` 订阅 + 自定义 SW `src/sw.ts` 展示通知，已打通，见 §3.3/§7.7）

## 7. 核心模块与关键逻辑（务必先理解再改）

### 7.1 调度算法（前后端同源）
- 后端 `backend/src/common/reminder-schedule.ts`，前端镜像 `frontend/src/utils/reminder-schedule.ts`——**改动必须双端同步并跑两边单测**
- 导出纯函数：
  - `computeNextTrigger(rule, from, startDate, endDate, timezone, times?)` → 下次触发 Date 或 null
  - `computeFollowingTrigger(rule, from, ...)` → 再下次（延迟/循环用）
  - `toLocal(d, tz)` / `localToUtc(...)`：时区转换（Intl formatToParts + 迭代校正，DST 安全）
- 语义要点（踩坑总结）：
  - repeat type：`once` / `daily` / `weekly`（daysOfWeek 多选）/ `monthly`（dayOfMonth，月末顺延）/ `interval`（intervalUnit: day/hour/week）
  - **`times: string[]`（HH:mm）多时间点**：daily/weekly 时每天从各 times 生成候选
  - **interval hour = 每天从 startDate 时刻开始循环到午夜**（不是简单的 +N 小时跨天）；interval day/week = 绝对步进
- 已由 23+ 单测覆盖（后端 `reminder-schedule.spec.ts`）

### 7.2 提醒实体字段（CreateReminderDto 要点）
```
category: 'medication'|'exercise'|'water'|'rest'|'work'|'custom'
categoryLabel/categoryIcon（custom 分类的文本与 emoji 图标）
title, repeatRule{type, daysOfWeek?, dayOfMonth?, intervalValue?, intervalUnit?}
startDate, endDate?, times?: string[]（多时间点 HH:mm）
content{text?, imageUrls?, videoUrl?, jumpTo?, waterAmountMl?, waterGoalMl?}
method{useFullScreen, sound, vibrationEnabled, gradualSound}
delaySettings{presetOptions?, customEnabled, maxDelayCount}
challenge{enabled, type:'photo', allowGallery}
showSkipButton, medicineId?（用药关联）
```
> **注意**：`content.waterAmountMl` / `waterGoalMl` 必须在 ReminderContentDto 声明（ValidationPipe forbidNonWhitelisted，未声明 → 400）。

### 7.3 统计口径（勿改，除非有明确需求）
- 完成率 = done / planned（**skip 不计入分母**，missed 计入）
- 连续天数：从今天（或昨天，今天未结）向前回溯全完成天数
- 分类统计：ReminderLog 存 category/amount **快照**（改分类不影响历史）
- 每日数据 = `remindersService.dayPlan(userId, dateStr)`（日历/统计复用）
- 喝水目标：`UserSetting.waterGoalMl`（默认 2000），每次确认喝水提醒扣 `content.waterAmountMl ?? 200`

### 7.4 库存事务与预警
`medicines.service.ts`：`deductStock` 在 `dataSource.transaction` 内完成 扣减 → 写 ReminderLog（含 stockDeducted 快照）→ 检查 ≤ threshold → 写 Notification（`type: 'low_stock'`）。扣减量 > 库存 → `STOCK_EXCEEDED` 回滚。幂等：UNIQUE(reminderId, scheduledTime) 保证重复 ack 只扣一次。

### 7.5 一键加入计划（事务要点）
`social.service.ts#joinPlan`：transaction 内 校验 planSnapshot → 解析 `reminderConfig[]`（category/title/repeatRule/startTime/content）→ 逐条创建提醒 → 写 PlanJoinRecord（UNIQUE(postId,userId) 幂等）→ `UPDATE post SET joinedCount = joinedCount + 1`（原子）。失败回滚零副作用。

### 7.6 漏服扫描（missed-scanner.ts）
`@Interval('missed-scan', 60_000)`（env 可调）：`nextTriggerAt < now` 且该时刻无任何响应记录 且 超时 > 30 分钟（用户级 `missedThresholdMinutes` 可调）→ 写 missed 日志 + 本人通知 + 亲友通知（`receiveMissed=true` 且有 `appUserId`；短信通道 P2 未接）。所有通知去重走 `NotificationLog.dedupKey`。

### 7.7 Web Push（push.service.ts + frontend/utils/push.ts + src/sw.ts）
- VAPID 密钥在 `.env`（生成：`npx web-push generate-vapid-keys`），未配置时 `sendToUser` 自动降级 no-op
- 前端流程：`isPushSupported()` → Notification.requestPermission → `navigator.serviceWorker.ready` → pushManager.subscribe（applicationServerKey = `GET /push/vapid-key`，**已按规范转换 base64url→Uint8Array**）→ `POST /devices` 注册
- `sendToUser(userId, {title, body, url})` 向该用户所有设备推送，404/410 失效订阅自动清理

### 8.1 TypeORM 关键陷阱（血泪史，勿重蹈）
1. **裸列必须显式 `type: 'varchar'`**：TypeORM 1.x 对 `string | null` 推断失败 → `DataTypeNotSupportedError: Data type Object`
2. **datetime 读取不带时区**：SQLite 返回 `"2026-08-18 15:59:00.000"`，必须用 `utcDateTime` transformer 读取时补 `Z`（`common/datetime.transformer.ts`）
3. **CreateDateColumn + transformer**：`to()` 对 undefined 必须返回 undefined（返回 null → NOT NULL constraint failed）
4. **禁用 save(loadedEntity) 更新**：TypeORM 1.1.0 对带 transformer 的列用 save() 会写入数据库旧值（DEBUG SQL 可见 `SET xxx = 0` 反向写入）。**所有更新一律 `repo.update({id, userId}, patch)`**（push.service 注释也标了）
5. **不要自定义 boolColumn/intColumn transformers**：1.1.0 的 `preparePersistentValue` 会二次转换导致 bool 写入 0
6. 新实体注册遗漏 → 运行时 500（Group 曾踩过）；**改完代码若行为"没变化"，先 `taskkill //F //IM node.exe` 重启**（增量编译的 dist 会过期，`rm -rf dist` 兜底）

## 11. 开发约定与工作流（必须遵守）

1. **git**：全程使用；`main` 分支；Conventional Commits；每个里程碑独立 commit（如 `feat(M4): ...`）
2. **文档同步**：完成任何任务 → 更新《项目计划与单元测试验收文档.md》勾选状态（☐→☑）与 §0 进度总表；新增 API → 同步本交接文档与 Swagger 自动生成
3. **测试先行**：纯逻辑（调度/统计/事务）先写单测再实现
4. **TypeORM 陷阱**：见 §8.1，改实体/更新逻辑时对照检查
5. **UI 每次改动** → 截图 → `ui-review` ≥ 8 再提交
6. **双端调度算法同步**：改 `reminder-schedule.ts` 必须同时改 `frontend/src/utils/reminder-schedule.ts` 并跑两边测试
7. 错误码规范：业务异常用 `{code, message}`（AllExceptionsFilter），不要在 controller 层 try/catch 吞错误
8. 所有页面/组件禁止直接 `import axios`，必须走 `services/http.ts`
9. 敏感信息（ARK_API_KEY 等）只用环境变量，代码/文档中出现即视为违规
