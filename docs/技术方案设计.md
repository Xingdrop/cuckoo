## 1. 设计目标与原则

| 原则 | 落地方式 |
|---|---|
| **模块通用** | 后端按领域模块化（NestJS Module），前端按 feature 组织；公共能力（通知/文件/认证/统计）独立为可复用模块 |
| **结构明晰** | 分层清晰：前端 `pages → features → services → api`；后端 `controller → service → repository`，禁止跨层直连 |
| **前后端分离** | 纯 REST API（JSON），前端零模板依赖后端；前后端可独立开发、独立部署、独立测试 |
| **数据库抽象** | Repository 模式 + TypeORM，SQLite 起步，**切换 PostgreSQL 仅改配置**（见 §5.4） |
| **可转移参数文档化** | 所有环境变量/API 通用参数集中在 `.env.example` 与本文档 §9；key 不硬编码 |
| **本地优先 + 云同步** | 核心提醒本地调度即时触发；后端权威兜底（漏服判定、Web Push、跨端同步） |
| **正式产品标准** | 安全基线、限流、审计、测试覆盖、视觉质量门禁、部署脚本齐全 |

### 2.1 提醒可靠性双通道设计（核心）

| 通道 | 触发时机 | 能力 | 局限 |
|---|---|---|---|
| **通道 A：本地调度** | 页面打开时，前端按 `nextTriggerAt` 设置 `setTimeout`/`setInterval` 精确调度 | 毫秒级准时、离线可用、可全屏弹窗 | 页面关闭后失效 |
| **通道 B：Web Push** | 后端定时扫描（每分钟），到期提醒通过 Web Push 推送到订阅设备 | 页面关闭仍可达、跨设备 | 依赖网络 + 用户订阅通知 |

策略：A 为主、B 为兜底；B 推送内容为"该提醒已到期"卡片，点击后打开 App 进入全屏弹窗页。**同一提醒 A/B 不重复打扰**：推送前查询 NotificationLog 是否已由本地通道上报（本地执行完成时会调用 `POST /reminders/:id/ack` 上报）。

### 2.2 本地优先 + 云同步

- 读取路径：优先本地缓存（IndexedDB），其次服务端
- 写入路径：先写本地（乐观更新）→ 异步同步到服务端 → 冲突以 `updatedAt` 较大者胜（last-write-wins）
- 删除采用**软删除**（`deletedAt`），同步时按 deletedAt 传播删除
- 离线队列：IndexedDB 中维护待同步操作队列，网络恢复后按序重放

## 3. 技术选型

### 3.1 前端

| 技术 | 选型 | 理由 |
|---|---|---|
| 框架 | React 19 + TypeScript | 生态最大、类型安全 |
| 构建 | Vite 8 | 秒级 HMR、原生 ESM |
| 样式 | Tailwind CSS v4 + CSS 变量设计系统 | 快速一致、Design Token 支持换肤（P2） |
| 状态 | Zustand | 轻量、无样板、可持久化中间件 |
| 路由 | React Router v7 | 标准方案 |
| 请求 | Axios + 拦截器（token 注入/401 刷新/错误归一化） | 统一错误处理 |
| 校验 | Zod（DTO 校验前后端共享 schema 语义） | 双端一致性 |
| 图表 | Recharts | 环形图/热力图/趋势图开箱即用 |
| 图标 | lucide-react | 线性图标风格统一 |
| 日期 | date-fns + lunar-javascript（农历/节日）；调度时区用 Intl（双端同源算法） | 提醒调度需要时区处理 |
| PWA | vite-plugin-pwa（Workbox） | manifest、Service Worker、离线缓存 |
| 测试 | Vitest + Testing Library（单测）、Playwright（E2E） | 与 Vite 同构、速度快 |

### 3.2 后端

| 技术 | 选型 | 理由 |
|---|---|---|
| 框架 | NestJS 11 | 模块化/DI/装饰器，强约束项目结构 |
| ORM | TypeORM | 与 NestJS 集成最佳、Repository 模式天然支持换库 |
| 数据库 | SQLite (better-sqlite3) | 零运维、事务支持完整；抽象层保证可迁 PostgreSQL |
| 认证 | @nestjs/jwt + Passport + bcryptjs | JWT 标准方案 |
| 校验 | class-validator + class-transformer（DTO） | 声明式管道校验 |
| 文档 | @nestjs/swagger（OpenAPI） | 自动生成 API 文档与类型 |
| 定时任务 | @nestjs/schedule | 漏服扫描、周报月报生成 |
| 推送 | web-push（VAPID） | Web Push 标准实现 |
| 安全 | helmet + @nestjs/throttler（已安装，**限流配置 M5 补：登录 5 次/分、普通 100 次/分/用户**） + CORS 白名单 | 安全头、限流、跨域控制 |
| 上传 | multer + sharp（图片压缩/缩略图） | 文件上传校验与图片处理 |
| 测试 | Jest + Supertest（单测/集成）、Playwright（E2E） | 标准链 |

### 3.3 存储方案

| 数据 | 方案 | 备注 |
|---|---|---|
| 业务数据 | SQLite（单文件，WAL 模式） | 每日冷备脚本；`DB_PATH` 可配置 |
| 图片/视频 | 本地 `uploads/` 目录 | Provider 抽象：后续可换 OSS/S3（§8.4） |
| 前端缓存 | IndexedDB（本地优先数据）+ CacheStorage（静态资源） | PWA |
| 推送订阅 | UserDevice 表 | 多设备管理 |

### 3.4 为什么不用 Flutter（本期）

本机未安装 Flutter/Android SDK（安装+配置成本高，且无法真机验证）；Web PWA 在本期可完成全部 P0/P1 功能并经过自动化测试与 UI 评审。**后端与数据层完全与平台无关**，原生 App 化（Flutter/RN）时仅需重写前端，接口与模型直接复用。

### 4.1 模块通用性约定

- **common 层禁止依赖 modules 层**（单向依赖）；modules 之间通过 service 接口协作，不互相 import 私有实现
- 每个领域模块对外只暴露 `XxxModule` 与公开 service 方法
- 前端 `services/api` 是唯一 HTTP 出口，页面/组件禁止直接 import axios
- 纯计算逻辑（调度计算、统计口径、重复规则展开）放 `utils/`（前端）/ `common`（后端），**必须有单元测试**

### 5.3 数据一致性要点

1. **库存扣减事务**：`completeReminder()` 中，Service 层开启事务：写 log → 更新 stock → 判定预警 → 写预警通知（NotificationLog 去重键 `lowstock:{medicineId}:{userId}`）
2. **漏服扫描**：`jobs/missed-scanner` 每分钟扫描 `next_trigger_at < now - threshold AND is_active AND 未响应` 的提醒 → 置 missed → 发漏服通知（去重键 `missed:{reminderId}:{scheduledTime}`）
3. **一键加入幂等**：`UNIQUE(post_id, user_id)` 保证；joinedCount 用事务内 `UPDATE posts SET joined_count = joined_count + 1` 原子自增
4. **重复规则展开**：`next_trigger_at` 由纯函数 `computeNextTrigger(rule, from)` 计算（含每月末日顺延），前端复用同一算法（JS 双端共享，放 `shared/` 或复制同源实现+双端单测）

### 5.4 SQLite → PostgreSQL 迁移路径

- 全部查询走 TypeORM Repository，禁止手写 SQL 方言
- 时间存储统一 UTC DATETIME；布尔用 BOOLEAN（TypeORM 自动映射）
- 迁移时：改 `typeorm.config.ts` 数据库类型 + 安装 `pg` 驱动，其余代码零改动
- 上线前跑一次 `npm run test:e2e` 全量回归

## 6. API 设计规范

> 完整路由清单与请求/响应示例见 `docs/API规范.md`（自动生成的 OpenAPI 为准）。此处为通用约定。

### 6.1 通用约定

| 项 | 约定 |
|---|---|
| 前缀 | `/api/v1` |
| 格式 | JSON（`Content-Type: application/json`） |
| 鉴权 | `Authorization: Bearer <JWT>`，除 `auth/*`、健康检查、公开帖子列表外均需鉴权 |
| 响应包装 | 成功直接返回数据对象；错误统一 `{ "code": "ERROR_CODE", "message": "中文可读信息", "details": {...} }` |
| 分页 | `?page=1&pageSize=20`，响应 `{ "items": [], "total": 100, "page": 1, "pageSize": 20 }`；pageSize ≤ 100 |
| 排序 | `?sort=createdAt&order=desc`，字段白名单校验 |
| 时区 | 时间统一 ISO 8601 UTC（`2026-08-17T04:00:00.000Z`），前端按用户时区渲染；客户端业务时间（重复规则）用本地时间+时区字段 |

| 限流 | `@nestjs/throttler`：登录/注册 5 次/分钟/IP；普通接口 100 次/分钟/用户 |
| 版本 | 破坏性变更升 `/v2`，非破坏性向后兼容 |

## 7. 核心模块设计

### 7.1 提醒调度引擎（前后端共享算法）

```
输入: repeat_rule + 基准时间 → computeNextTrigger() → next_trigger_at
规则展开（纯函数，双端同源）:
  once     → start_date
  daily    → 每 N 天
  weekly   → 最近的 daysOfWeek
  monthly  → 指定 dayOfMonth（≥28 时末日顺延）
  interval → 每 N hour/day/week
```

**前端调度**：`features/reminders/scheduler.ts` 维护触发表（按 next_trigger_at 排序），最短到期项用 `setTimeout` 调度；触发后进入全屏弹窗流程；完成/延迟/跳过 → 调用 ack API + 本地记录。

**后端调度**：`jobs/` 每分钟扫描：
1. `next_trigger_at ≤ now` 且 is_active → 触发 Web Push（若有订阅设备）
2. 超时未响应 → 漏服判定（§7.3）
3. 响应后重算 `next_trigger_at`（重复提醒）

### 7.2 全屏弹窗与拍照打卡流程

```
触发 → 全屏遮罩（overlay portal）+ Web 通知 → 挑战开启? ─是→ 拍照/相册 → 上传
      └──────────────┬───────────────┘                        │
               完成/延迟/跳过 ◄──── 自动完成(可配置) ◄─────────┘
      → ack API(幂等) → 本地更新 → 用药? → 事务扣库存 → 预警判定
```

### 7.3 漏服判定（后端权威）

- 扫描条件：`status 为空（未响应）AND now - next_trigger_at > missed_threshold`
- 处理：置 missed、生成漏服通知（用户 + 开启 receiveMissed 的亲友）、NotificationLog 去重
- 用户设置阈值 `missedThresholdMinutes`（全局默认 30，可在药品/提醒级覆盖）

### 7.4 Web Push 通知服务（可换 Provider）

```
NotificationService (抽象接口)
 ├─ PushService(web-push)   → 遍历用户 devices 发送
 ├─ InAppService            → 写 notifications 表 + 通知中心
 └─ SmsService(预留接口)    → 本期 no-op，P2 接阿里云/Twilio
```
- 发送前查 NotificationLog `dedup_key` 去重；失败重试 2 次（指数退避），记录 status

### 7.5 统计与报告

- **实时口径**：`/stats/dashboard` 从 reminder_logs 聚合当日数据（SQLite 索引覆盖）
- **快照**：每日 00:30 生成 stats_snapshots（供热力图/周报月报回溯，避免重算）
- **周报**：每周一 08:00 任务生成 → 写 notifications（类型 weekly_report）→ 前端展示页
- **月报**：每月 1 日 08:00 同上；热力图数据按月聚合快照
- **成就**：每次 ack/日报生成后调用 `AchievementService.check()`，按 rules 表逐条匹配，新增成就写表 + 通知 + 可分享卡片

### 7.6 一键加入计划

```
POST /posts/:id/join (Idempotency-Key 防重)
  → 事务: 校验 post.plan_snapshot 版本 → 解析快照(JSON Schema 校验)
  → 创建 reminders（用户可先 PUT /reminders/:id 修改）
  → 写 plan_join_records(UNIQUE 防重) → posts.joined_count+1
退出: DELETE /posts/:id/join → is_active=false + 软删提醒 + joined_count-1
```

### 7.7 认证与会话

- 注册：手机号/用户名 + 密码（bcrypt cost 10）；手机号验证码通道预留（P2 短信）
- JWT：`HS256`，payload `{ sub, username }`，7d 有效；401 时前端拦截器统一跳登录（保留回跳路径）
- 用户注销：软删除用户 + 异步清理关联数据（任务），保留 30 天审计日志

## 8. 安全、隐私与部署

### 8.1 安全基线

| 项 | 措施 |
|---|---|
| 传输 | 全站 HTTPS（生产）；HSTS 头 |
| 头部 | helmet：CSP（放行 VAPID 端点与静态资源）、X-Content-Type-Options 等 |
| 认证 | bcrypt 密码哈希、JWT 过期、登录限流、失败锁定（5 次/15 分钟） |
| 授权 | 所有资源查询强制带 userId 条件 + 资源归属校验（防水平越权） |
| 输入 | DTO class-validator 白名单校验；Zod 前端同步校验 |
| 上传 | 扩展名+MIME+魔数三重校验；sharp 重编码图片（去 EXIF，剥离 GPS）；文件名 UUID 化 |
| 注入 | TypeORM 参数化查询；敏感词过滤防 XSS（前端渲染统一转义） |
| 限流 | 全接口 + 登录/注册更严 |
| 审计 | 关键操作（注册/注销/删除/亲友变更）写 audit log 表 |

### 8.2 隐私合规（个保法/GDPR）

- 隐私政策页（P0 提供，含数据收集清单：手机号、健康目标、打卡照片）
- 拍照打卡照片默认**仅本人可见**；分享到社区需用户二次确认
- 数据导出：`POST /users/export` → JSON 全量打包下载（24h 有效链接）
- 注销即删除（30 天缓冲期内可撤销，缓冲期后物理清除）
- 亲友通知需**接收方同意**（短信通道 P2 时验证码授权）

### 8.3 部署方案

| 环境 | 方案 |
|---|---|
| 开发 | `npm run dev`（Vite 5173 + NestJS 3000，Vite proxy `/api` → 3000） |
| 生产（本期） | Nginx（静态资源 + 反代 `/api`）+ PM2（`backend`）+ SQLite 每日冷备 |
| 可选扩展 | Docker Compose（前端 nginx 镜像 + 后端 node 镜像 + volume 持久化），Dockerfile 已规划在 `tools/scripts/` |

部署手册（含 Nginx 配置示例、PM2 配置、备份恢复脚本）见 `docs/部署手册.md`。

## 11. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
