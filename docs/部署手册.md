# 布谷（Cuckoo）部署手册

> 版本：v1.0 ｜ 日期：2026-08-29 ｜ 适用：生产环境（Nginx + PM2 主方案，Docker Compose 可选）
> 关联文档：《技术方案设计.md》§8.3 部署方案、《项目计划与单元测试验收文档.md》§9 Release Checklist

---

## 1. 部署架构

```
浏览器 ──HTTPS──> Nginx :443
                   ├── /            → frontend/dist（静态资源，SPA fallback → index.html）
                   ├── /uploads/    → backend/uploads/（图片访问）
                   └── /api/        → 反向代理 → PM2 进程 :3000（NestJS）
                                          └── SQLite 文件 data/cuckoo.sqlite（WAL）
                                              └── 每日备份 → 备份目录（cron）
```

- 前端静态构建：`frontend/dist`（含 Service Worker 与 PWA manifest；**必须配 HTTPS**，否则 SW/推送不可用）
- 后端进程：`backend/dist/main.js`（PM2 管理，单实例；登录失败锁定为内存计数，多实例需共享存储）
- Web Push：`backend/.env` 需配置 VAPID 密钥（`npx web-push generate-vapid-keys`）

## 2. 目录结构（生产建议）

```
/opt/cuckoo/
├── frontend/          # 前端构建产物（dist/）
├── backend/
│   ├── dist/          # 后端编译产物
│   ├── data/          # SQLite 数据库（+ -wal/-shm）
│   ├── uploads/       # 上传图片
│   └── .env           # 生产环境变量（见 §4）
├── logs/              # PM2 日志
└── backups/           # 数据库备份
```

## 3. Nginx 配置示例

```nginx
server {
    listen 443 ssl http2;
    server_name cuckoo.example.com;

    ssl_certificate     /etc/letsencrypt/live/cuckoo.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/cuckoo.example.com/privkey.pem;

    # 前端 SPA（history 路由 fallback）
    root /opt/cuckoo/frontend/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # 上传图片
    location /uploads/ {
        alias /opt/cuckoo/backend/uploads/;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # 后端 API
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
        client_max_body_size 12m;   # 略大于 MAX_FILE_SIZE（10MB）
    }
}

# HTTP → HTTPS
server {
    listen 80;
    server_name cuckoo.example.com;
    return 301 https://$host$request_uri;
}
```

> PWA 必需头（由 vite-plugin-pwa 生成的 sw.js 已处理）——若需自定义安全头，在 Nginx 增加
> `add_header Service-Worker-Allowed "/";`（默认已允许根路径，一般无需）。

## 4. 后端生产环境变量（backend/.env）

```bash
NODE_ENV=production            # 关闭 Swagger；synchronize 自动关闭（见 §6）
PORT=3000
CORS_ORIGINS=https://cuckoo.example.com
DB_PATH=data/cuckoo.sqlite
DB_WAL=true
JWT_SECRET=<强随机串>           # node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
JWT_EXPIRES_IN=7d
UPLOAD_DIR=uploads
MAX_FILE_SIZE=10485760
VAPID_PUBLIC_KEY=<web-push 生成>    # 不配则推送模块降级 no-op（不报错）
VAPID_PRIVATE_KEY=<web-push 生成>
VAPID_SUBJECT=mailto:admin@cuckoo.example.com
MISSED_SCAN_INTERVAL_MS=60000
WEEKLY_REPORT_CRON=0 8 * * 1
MONTHLY_REPORT_CRON=0 8 1 * *
SMS_PROVIDER=none
SEED_DEMO_DATA=true
```

**检查项（Release Checklist 对应）**：JWT_SECRET/VAPID 必须替换；`npm audit` 高危 0；postman 验证 `curl https://cuckoo.example.com/api/v1/health`。

## 5. MySQL/Redis 说明

> 本项目为 SQLite 单文件部署。若后续迁移 PostgreSQL，仅需：
> 1. `npm i pg`；2. `app.module.ts` 将 `type: 'better-sqlite3'` 改为 `postgres` + 连接参数；
> 3. 关闭 synchronize，改用 TypeORM migration（见 §6）。

---

## 6. 数据库初始化与 Migration 策略

- **开发/首次部署**：`NODE_ENV=development` + `synchronize: true` 自动建表（当前 M5 之前项目一直如此）。
- **生产**：`NODE_ENV=production` 时 `synchronize` 自动为 false——**需先手工初始化表结构**：
  ```bash
  # 方式一（推荐，首启）：先用同步模式启动一次生成表，再切 production
  # 方式二：用 migration 生成基线
  cd backend
  npx typeorm migration:generate src/migrations/InitSchema -d src/config/typeorm.config.ts
  npx typeorm migration:run -d src/config/typeorm.config.ts
  ```
- 后续实体变更：`migration:generate` → `migration:run`，禁止改生产库结构后重启依赖 synchronize。

## 7. PM2 配置

```bash
cd /opt/cuckoo/backend
npm ci --omit=dev
npm run build
pm2 start dist/main.js --name cuckoo-api --max-memory-restart 400M --time
pm2 save && pm2 startup
```

日志：`logs/cuckoo-api-out.log` / `-error.log`（PM2 默认目录，用 `PM2_HOME=/opt/cuckoo/logs/pm2`）。

---

## 8. 数据备份（tools/scripts/backup.sh）

```bash
# 每日 02:00 备份 SQLite（WAL 检查点 + 复制 -wal/-shm 或直接 sqlite3 .backup）
0 2 * * * /opt/cuckoo/tools/scripts/backup.sh >> /var/log/cuckoo-backup.log 2>&1
```

Backup 脚本（已随仓库提供 `tools/scripts/backup.sh`）：
- 使用 `sqlite3 data/cuckoo.sqlite ".backup backups/cuckoo-YYYYmmdd-HHMMSS.sqlite"`（WAL 安全）
- 保留最近 14 份，自动清理过期备份
- **恢复演练**（Release Checklist）：从备份文件启动一次后端并 `GET /health` 通过

## 9. Docker Compose（可选）

```yaml
services:
  api:
    build: ./backend
    environment:
      NODE_ENV: production
      JWT_SECRET: ${JWT_SECRET}
      VAPID_PUBLIC_KEY: ${VAPID_PUBLIC_KEY}
      VAPID_PRIVATE_KEY: ${VAPID_PRIVATE_KEY}
      CORS_ORIGINS: https://cuckoo.example.com
    volumes:
      - ./backend/data:/app/data
      - ./backend/uploads:/app/uploads
    restart: unless-stopped

  web:
    image: nginx:alpine
    volumes:
      - ./frontend/dist:/usr/share/nginx/html:ro
      - ./deploy/nginx.conf:/etc/nginx/conf.d/default.conf:ro
    ports: ["443:443", "80:80"]
    depends_on: [api]
    restart: unless-stopped
```
